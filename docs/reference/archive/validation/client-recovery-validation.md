## 제품 수정과 초기 검증

문제 해결의 복구 적용 성공을 후속 조회와 구분했다. 적용 후 네트워크/파일 상태 검사가 실패하면 `파일 복구 완료 · 상태 재확인 필요`로 표시하고 조회만 재시도한다. 복구/복원 적용 성공 시 같은 선택의 이전 재개 힌트를 해제하며, 확인 취소/조회만/적용 전 실패는 유지한다. 복원 단계는 다운로드 취소 컨트롤을 종료한다.

내부 테스트용 복원 함수 주입은 운영 CLI나 설정에 노출하지 않는다. 외부 schema·IPC v1·CLI 형식 변경은 없다.

Windows 관련 회귀56개, 전체714개(698+16), 실패/skip0. 새 회귀는 두 모드의 복구 성공 후 조회 장애/파일 이상/commit 결과, 조회 전용 재시도, 복원 적용 중 취소 제거, 적용 실패/조회만의 재개 정보 보존을 검사했다. candidate-01 게시 CLI·console Agent HTTP 요청 서명·준비도·작업 취소/재개 E2E 통과. 제품 소스 hash는`5eae0ed25364c9746f09270d5dae6d8dc13febfbcb25ff03215acc44f9414fae`다. publish 당시HEAD2a6d2d7/제품 변경 존재를 기록했으며 최종 후보는 사후 소스 hash를 다시 대조한다.

WSL 전체714개도 실패/skip0으로 통과했다. 동기화 명령에서 잘못 지정한 solution 파일명 때문에tar 진단이 있었으나 src/tools와props는 전달됐으며 기존 mirror의 프로젝트 참조로 전체 회귀가 실행됐다. mirror를Git clean checkout이나새Linux publish 증거로 표시하지 않는다. 이번 후보의Linux publish/HTTPS E2E는 아직 미실행이다.

## 시험 도구와 실제 GUI 중단

합성 앱의 requested/watchdog 종료 사유, 정확한 생존 시도 검사, payload/backup의 lock 이름 파일 비교, 기존 설치 잠금 안의 엄격한 runtime/활성 작업 검사, 프로필별 반복 설정 오류/해시 보호 복원, 프록시 세션 요약 보존과 정확한 repair commit 후 한 번의 인증된 Catalog503 제어를 추가했다. 도구19개·프록시3개 통과. 새 합성 실행 파일을 publish했고 관리형/portable 네 독립 폴더를 미설치로 준비하여 사전 점검했다. 인증은 사전 점검에서 not-checked로 표시하며 익명401 readiness를 인증 성공으로 보충하지 않는다.

관리형 일반 초기 GUI의 추천 미지정 안내·비활성 주 버튼을 직접 캡처했다. 이어서 마우스 시험을 시작하기 전에 사용자의 물리 ESC로 Computer Use가 중단됐다. 설치/실행/취소/복구/복원의 실제 클릭은 이번 후보에서0건이며 다른 세 창은 시작만 했다. 도구의 미설치 조회/설정 준비는 GUI 수용 통과가 아니다. USER-02/UI-02는75%, USER-03은50%, UI-03은75%를 유지한다.

계획 조건은1440×900이지만 이번 일반 창이 기록한 실제 진단은1920×1080/작업영역1920×1032/RenderScaling1/앱글자1/고대비 끔이다. 실제값을 기록하며1440×900 시험으로 계산하지 않는다. 다음 입력 재개 시 현재 실제 화면 조건을 다시 대조한다. 이전final-05는 별도 이력이다. 원시 화면은 비공개 publish/recovery/screens/mg-awaiting-promotion.png이며 키/로그/DB/시험 설치는 Git에 포함하지 않는다.
