# GUI 사용자 가이드

> 현재 가이드 / 문서 점검 2026-10-03 / codex/client-editions-ux-acceptance. 아래 실제 통과는 과거 후보 이력입니다. 마우스 시험 재개 요청을 받았고 현재 세션 Disc/입력 거부로 새 적용은 미실행입니다. [이번 기록](archive/validation/client-editions-validation.md), [보완 목록](../../IMPROVEMENTS.md)을 확인하세요.

취소 요청은 작업 완료와 다릅니다. 적용 전에는 작업자/안전한 복구 종료를 기다리고, 설치 commit 후에는 설치 완료·실행 생략/상태 재확인 안내를 따릅니다. 이미 시작한 앱은 취소로 종료하지 않습니다. 이번에는 관련 코드/headless만 검증했으며 실제 취소 버튼 수용은 재개 후 필요합니다.

취소가 끝나고 같은 배포가 선택돼 있으면 ‘다운로드 재개’를 사용할 수 있습니다. 온라인 권한/Manifest를 다시 확인하고 파일을 검증하며 완료 후 앱을 자동 실행하지 않습니다. 다른 버전 선택이나 실행 상태 차단이 있으면 재개하지 않습니다. GUI를 재시작한 뒤의 기존 작업 관리는 공통 CLI `operation status/resume`를 사용합니다.

현재 GUI는 Windows 합성 앱으로 시험하며 Linux는 CLI 기준입니다. Linux 데스크톱 GUI에는 X11/Wayland가 필요합니다. 고정 후보 `8ce5060`의 관리형·portable 설치/업데이트·수명·개발자 복구/복원·preview 거부를 실제 확인했습니다. UI-01은1920×1080의 검증된 기본 배율 범위에서 수용했고, 남은 오류/개발자 확인(UI-02)과 접근성(UI-03)은 별도 대기입니다. 이전 게시본 `ab37fcb` 결과는 별도 이력으로 보존합니다. [이번 증거·남은 조건](archive/validation/ui-acceptance-finalization.md)·[개선 대장](../../IMPROVEMENTS.md)을 확인하세요.

## 시작

```powershell
.\publish\win-x64\UeDtLauncher.exe
.\publish\win-x64\UeDtLauncher.exe gui --config C:\ue-dt\gui.config.json
```

GUI 표시 설정은 명시한 `--config` → 실행 파일 옆 `launcher.config.json` → 관리 설정 순입니다. 관리형 DistributionServer는 Agent의 보호 설정도 별도로 필요합니다. 서버·토큰·공개키·설치 경로는 [설정 레퍼런스](guide-03-launcher-usage.md)를 따릅니다.

## 일반 사용자와 개발자

| 항목 | general | developer |
| --- | --- | --- |
| 화면 | 실행·상태·설정 중심 | 배포·유지보수·진단 도구 포함 |
| 기본 선택 | prod / stable / latest | 환경·채널·latest/exact 선택 |
| OS | 현재 실행 OS 고정 | 현재 실행 OS 고정 |
| 권한 | 서버 허용 릴리스만 | 서버 허용 릴리스만 |

일반·개발자 화면은 각각의 실행 파일에 고정됩니다. 개발자 EXE를 실행해도 미허용 배포를 받을 수 없습니다. 프로젝트 목록은 서버가 허용한 현재 플랫폼 릴리스로 구성됩니다.

## 사용 순서

1. 시작 시 관리형은 업데이트 서비스·배포 목록·설치 상태를, portable은 로컬 모드의 배포 목록·설치 상태를 자동 확인합니다. 여러 프로젝트가 있을 때만 선택/검색합니다.
2. 설치 필요·업데이트 가능·최신 상태를 확인합니다. 필요하면 상태 새로고침을 누릅니다.
3. 설치/업데이트/실행 주 동작을 누릅니다. 관리형 설치는 Agent가 파일을 검증·설치하고 GUI가 사용자 세션에서 앱을 실행합니다. Portable은 현재 계정의 로컬 엔진으로 처리하며 Agent 연결을 요구하지 않습니다.
4. 오류가 나면 안내 문구와 지원 ID를 확인하고 설정에서 지원 로그 ZIP을 저장합니다. 일반 화면에는 내부 예외·설치 경로를 노출하지 않습니다.

진행률은 다운로드 수치와 단계별 표시를 함께 사용합니다. 100%는 런처 작업 완료이지 UE 로딩·맵 초기화 완료를 뜻하지 않습니다.

일반 화면은 최신 배포가 아직 설치되지 않아도 동일 프로젝트/환경/채널/OS의 이전 설치 기록이 확인되면 `기존 설치 버전 / 최신 배포 버전 / 업데이트 후 실행`으로 안내합니다. 이전 기록은 파일 정상성 보증이 아니며 새 버전은 별도 폴더에 설치합니다. 다른 버전·트랙으로 실행을 몰래 바꾸지 않습니다. 구형 Agent에서는 기존 미설치 표시가 유지될 수 있습니다.

상태 확인은 새 배포 목록을 먼저 조회합니다. 서비스가 꺼져 있으면 IPC 연결 시도는 3초 후 실패 안내로 전환하고, 연결된 다운로드/복구 작업은 기존 작업 제한을 따릅니다. 조회 재시도는 파일 설치나 앱 실행을 하지 않습니다.

## 화면·접근성

일반 화면은 밝은 POSCO DX 색상, 개발자는 어두운 업무용 화면입니다. 창이 좁으면 프로젝트 선택이 상단으로 이동하고 개발자 상세 정보/로그가 탭으로 바뀝니다. 실행·상태·진행 영역은 하단에 남고 긴 본문만 스크롤합니다.

| 조작 | 동작 |
|---|---|
| 설정 → 글자 크기 → 적용 | 100/125/150/200%, 사용자별 저장 |
| 설정 → 앱 고대비 → 적용 | 검정/흰색 고대비. OS 고대비 요청도 반영 |
| Tab / Shift+Tab | 컨트롤 이동, 포커스 테두리 표시 |
| 프로젝트 목록 방향키 | 프로젝트 선택(서버 권한은 그대로) |
| F5 / F6 | 활성 상태의 주 작업 / 상태 확인 |
| 대화창 Escape | 취소/닫기, 원래 버튼으로 포커스 복원 |

대화창은 안전한 취소/닫기에 기본 포커스를 두며 Enter만으로 복원을 자동 승인하지 않습니다. 실패한 작업의 다시 시도는 작업 종류와 선택을 유지하고, 선택이 바뀌면 먼저 확인합니다. 유지보수/도움말 제목과 상세/로그 탭에도 글자 배율을 적용합니다. 작은 창의 작업 상세는 Tab으로 이동한 뒤 스크롤할 수 있습니다. 지원 ZIP은 사용자별 로컬 지원 폴더에 저장하며 자동 전송하지 않습니다. 이번 화면 수용은1920×1080의 검증된 기본 배율에 한정합니다. 다른 화면 조건과 내레이터 음성은 [후속 검증 항목](archive/validation/ui-acceptance-finalization.md)입니다.

> **추가 테스트 필요:** 1366×768·1280×720 등 다른 해상도. OS 배율125/150%, 큰 글자·고대비 최악 조건도 이번 검증 완료 범위에 포함하지 않으며 후속으로 시험합니다.

## 개발자 선택·복구

환경·채널 선택 후 `latest` 또는 `exact`를 고릅니다. `exact`에서는 서버 목록의 버전을 선택합니다. 선택값은 현재 화면의 작업에 적용되며 설정 파일 저장 기능으로 취급하지 않습니다. 실행 확인창의 프로젝트·환경·채널·확정 버전을 확인하세요. 늦은 응답이나 Catalog 변경이 확인한 버전을 다른 버전으로 대체하지 않습니다.

- 업데이트: 앱 실행 없이 선택 버전을 설치합니다.
- 검증/복구: 서명된 Manifest 기준으로 파일을 다시 받아 검증·적용합니다. 명시적 repair는 정상 파일도 다시 받을 수 있습니다.
- 이전 버전 사용: 허용된 버전을 `exact`로 선택해 설치·실행합니다. 각 버전은 별도 디렉터리에 남습니다.
- 롤백: 관리형과 portable 모두 정확한 버전 경로와 확인한 백업을 다시 검사합니다. 확인 후 선택 설치의 보관된 backup을 복원합니다. 취소하면 적용하지 않습니다. 별도 설치된 v2를 v1 경로로 바꾸는 기능이 아닙니다. 최초 설치의 빈 backup을 정상 이전 버전으로 가정하지 마세요. 새 관리형 확인창은 Agent의 backup ID·생성시각·현재/복원 버전을 표시합니다. 복원 정보가 불명확하면 적용하지 않습니다. 최초 설치 백업은 미설치 상태로의 복원(설치 파일 제거 가능)을 명시합니다. 확인 후 백업이 바뀌면 적용을 거부하고 새 확인이 필요합니다. Agent의 rollback-preview-v1 지원이 필요합니다.
- 캐시/백업 정리: 관리형에서는 안전한 Agent 관리 명령이 없어 비활성화합니다. GUI가 보호 폴더를 직접 정리하지 않습니다. portable staging 정리는 서버 릴리스·전체 버전 삭제 기능이 아닙니다.
- 로그/진단 내보내기: 공유 전 민감정보·프로젝트 정보를 확인합니다.

정상 백업 복원 시험은 손상→복구→정상 파일 확인→정상 상태에서 추가 복구로 백업 생성→백업 전체 해시 확인→재손상→복원 순서입니다. 손상 파일을 고친 repair의 직전 백업을 정상 백업이라고 가정하지 마세요. 이는 합성 시험 순서이며 운영 파일을 일부러 손상시키라는 안내가 아닙니다.

## 실행 중과 문제 해결

명시적 승격 서버에서 추천이 없으면 ‘관리자가 실행 버전을 지정하지 않았습니다.’와 비활성 주 버튼을 표시합니다. PC 권한이 맞아도 첫 버전은 관리자가 promote해야 합니다. 상태 확인으로 다시 조회할 수 있습니다. 개발자 exact는 허용된 미승격판도 선택할 수 있으며, 프로필 변경으로 서버 권한이 늘어나지는 않습니다.

GUI를 닫는 것만으로 DT 앱이 종료되지는 않습니다. 실행 중에는 주 실행 버튼이 비활성화되며, 프로그램 정상 종료 후 상태 새로고침을 사용하세요. Pending/Unknown은 관리자 점검이 필요하며 PID/runtime 파일을 지워 우회하지 않습니다. [상태별 명령](runtime-safety.md)

문제 해결은 점검 → 이미 설치된 선택 버전의 손상 복구 → 재검증 순서입니다. 관리형은 서비스도 확인하고 portable은 Agent를 호출하지 않습니다. **미설치 또는 아직 받지 않은 새 버전은 문제 해결에서 설치하지 않고 주 설치/업데이트 버튼으로 안내합니다.** 정상 설치는 점검 성공으로 끝나며 앱을 자동 실행하지 않습니다. 실행 중/불명 상태를 복구 성공으로 표시하거나 그 이유만으로 rollback을 제안하지 않습니다. 실패한 repair에 backup이 있는 경우에도 같은 모드/선택의 새 preview와 확인 후에만 rollback을 제안합니다.

| 증상 | 확인 |
| --- | --- |
| 화면 종류가 예상과 다름 | 실제 EXE와 `--build-info`의 edition 확인. config의 clientProfile은 GUI 종류를 바꾸지 않음 |
| 프로젝트·버전이 없음 | 서버 승인 상태, 토큰·IP·grant, 현재 OS·환경·채널 |
| Agent 연결 실패 | 서비스 실행, IPC 접근 권한, 관리 설정 존재 |
| 401/403 | 토큰 유효성, 실제 접속 IP·서버 정책; 프로필 변경으로 해결하지 않음 |
| 서명/TLS 실패 | keyId·공개키·사내 CA·서버 주소; 검증을 끄지 않음 |
| 설치 후 시작 실패 | 실제 UE 실행 파일·Linux 실행권한·런타임 의존성·앱 로그 |
| 프로그램 저장 경로 준비 실패 | 관리자에게 runtimeData 설정·현재 실행 사용자 권한·경로 중첩 확인 요청. 검사를 끄거나 설치 폴더로 우회하지 않음 |
